# Cold-start backlog: serial G1 harness chain with the eval corpus and arming baseline frozen

_Recorded 20260922-150203 by the NIGHTSHIFT planner._

## Context
First planning pass. Backlog, done, parked and worker followups are all empty, and the roadmap already carries one milestone per charter goal (M1/G1, M2/G2, M3/G3), so no milestone was added. The planner sandbox mounts only the plan directory — /plan and /work are the same inode and the job-application-agent repo is not visible — so tasks were derived from the charter's explicitly named files and per-goal definitions of done rather than from code inspection. Assumption recorded: the module paths named in the charter (src/url_heuristics.py, src/page_signals.py, src/crawler_engine.py, src/orchestrator.py, src/notifier.py, src/telegram_api.py, src/bot_service.py) and the recorded corpus under evals/runs/** exist as described; a worker that finds otherwise should report blocked with the actual layout rather than improvising. G2 is defined as beating a baseline that does not exist yet, and G2/G3 work is only measurable once the harness runs, so the chain is strictly serial.

## Decision
Sequence thirteen tasks in charter priority order G1 > G2 > G3, each citing one goal and one milestone, each gated by depends_on. M1 splits into loader, metrics, replay, report, frozen baseline, README — one testable unit each. M2 takes the two metrics the charter names as must-improve (aggregator-drop, then posting-shape) before touching dedup. M3 covers match rationale, repeat-notification impossibility, failure text, and remaining message paths. Integrity controls: evals/runs/** is protected in every task so no worker can improve a score by editing the fixtures; evals/** as a whole is protected in all M2 and M3 tasks so the metric definitions and the frozen arming baseline cannot be moved to manufacture an improvement; the deployment non-goals (Dockerfile, docker-compose.yml, .github/**, pyproject.toml, uv.lock) are protected everywhere. src/** is protected throughout M1 except T-0003, where an import seam may genuinely be required and run_mock_test.py is an acceptance gate to prove behaviour is unchanged. Every M2/M3 task carries run_mock_test.py as acceptance; max_diff_lines stays between 150 and 400, well under the 800 ceiling.

## Consequences
The critical path to G1 is six sequential tasks, so no G2 work can start for several worker cycles; this is accepted because the charter defines G2 relative to a baseline only T-0005 can produce. Narrow allowed_paths mean a worker whose fix needs a file outside its task will have to report a followup instead of proceeding, costing an iteration but keeping diffs attributable and reversible. Freezing the baseline in T-0005 means a later corpus expansion would invalidate the comparison and require an explicit new task rather than a silent re-record. The per-task allowed_paths were written against charter-declared file names that this planner could not verify on disk; if they are stale, the affected tasks fail fast on path rejection rather than editing the wrong file, and the resulting followups will correct the next planning pass.
