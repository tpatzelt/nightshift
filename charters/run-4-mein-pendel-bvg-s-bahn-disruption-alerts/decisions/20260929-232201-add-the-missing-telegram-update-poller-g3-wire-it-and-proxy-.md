# Add the missing Telegram update poller (G3), wire it and proxy-trusted IPs into compose (G4), and retry parked T-0034 as T-0038 (G5)

_Recorded 20260929-232201 by the NIGHTSHIFT planner._

## Context
The backlog was empty. G1 is still blocked: its definition of done needs recorded real fixtures, and live HAFAS recording is blocked in this sandbox (ADR 20260929-125118; T-0016/T-0017/T-0018/T-0020–T-0022 parked). I read the code and found two real gaps. (1) G3: telegram_link.handle_update has no production caller. runner.py only runs the Scheduler, so a user who opens the /start deep link is never linked. Earlier ADRs deferred this poller explicitly. (2) G4/G5: the web container sits behind Caddy with no proxy trust configured. The per-IP limiter keys on request.client.host, which is Caddy's container IP, so all visitors share one 60 req/min bucket. The T-0033 review and the ratelimit.py docstring both point to uvicorn's forwarded-allow-ips as the fix. T-0034 (legal pages) was parked after attempt 2. Everything was accepted except the Datenschutz IP sentence, which overstated retention and promised no logging.

## Decision
Add T-0036 (G3/M3): the new module pendel.telegram_poll. It calls getUpdates, passes each update to handle_update, keeps the offset in memory (safe because tokens are single-use), is error-isolated, exits 0 when no token is configured, and is tested only through httpx.MockTransport. Add T-0037 (G4/M4), which depends on T-0036: a `telegram` compose service with restart: on-failure and the healthcheck disabled. It also documents FORWARDED_ALLOW_IPS restricted to the caddy_network subnet, with a placeholder value only and no LAN IPs, after the worker checks the installed uvicorn's behaviour. Add T-0038 (G5/M5), a retry of T-0034 with the reviewer's exact wording guidance. Order follows G3 > G4 > G5. Assumptions, taking the conservative reading: Docker is not run; poller offset persistence is left out; ratelimit.py and the Dockerfile are unchanged, because the env var configures uvicorn without a code change; no real message service is ever contacted. T-0034 stays parked because IDs are never reused.

## Consequences
Once these land, Telegram linking works in production as well as in tests. The per-IP limiter throttles individual visitors once the operator sets FORWARDED_ALLOW_IPS. G5's definition of done (legal pages linked in the footer, delete tested, 429 tested) is met. Still open and needing a human: live HAFAS recording access for G1 (the parked recording chain and T-0018); running `docker build`, the container healthcheck and `docker compose config` for G4; and filling in real Impressum details in place of the placeholders.
